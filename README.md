## What this repository is for

This is the smallest of the three ioPay Wallet guide collections, and the one a reader should open before installing anything. Its twelve pages answer two questions that look like one. The first is whether a desktop self-custody wallet is the right tool for how you hold IOTX, and how ioPay Wallet compares with other desktop wallets once custody, address handling and staking are compared on criteria rather than on preference. The second is which build you are actually looking at: more than one desktop application has carried this name, and a review quoting an older version describes a different product.

The pages are written for a reader who has not decided yet, and for one who has installed something and wants to confirm what it is. They avoid rankings, because a ranking compresses several trade-offs into a number nobody can audit. Where a comparison is made, the criterion is named and the other side is described in its own terms. Where the project publishes nothing - an endorsement, an audit report, a checksum - the page says so, and the absence is treated as information rather than as something to talk around.

## Who it is for

- **A first-time wallet buyer.** You want to know what a wallet actually controls before choosing one, not a feature list.
- **Someone comparing desktop wallets.** You already hold IOTX and want the trade-offs stated plainly, including the ones that make this wallet a poor fit.
- **Someone checking an install.** You downloaded something and want to confirm the version, the source and the backup model match the current release.

## How to read a wallet comparison

Start with the criterion, not the verdict. A comparison that says one wallet is better has usually chosen a criterion and hidden it; a comparison that says one is better at custody and another at convenience has told you something you can act on. The pages here name the criterion in the heading or the first sentence, apply it to both sides, and leave the weighting to the reader, because the right weighting depends on how much value is at stake and how often it moves.

Then check what the comparison is comparing. A browser extension and a desktop application are different surfaces with different failure modes: the extension shares a browser's attack surface and is convenient, while the desktop app keeps keys outside the pages you visit and asks you to move between windows. A mobile app and a desktop build are different products even when they share a chain and a phrase. Comparing across those categories without saying so is how a reader ends up choosing a form factor they did not want.

Finally, date the claim. A review that quotes a version is describing the build of that version, and this account has already seen a twelve-word phrase model replaced by phrase, key and keystore imports. Version numbers age faster than the reasoning around them, which is why the release page and the build-identification page are part of this collection rather than an appendix to it.

## Common first questions

### Is a desktop wallet safer than an extension?

Neither is automatically safer. A desktop application keeps keys away from pages you browse, while an extension is convenient and lives inside the browser; the difference that matters is whether the key leaves your machine.

### Does ioPay Wallet hold my funds?

No. The keys are stored on your computer and the funds are on the IoTeX chain at an address derived from those keys. The application signs; it does not custody.

### Why do reviews show different versions?

Because more than one desktop client has carried the name, and because reviews are not updated when a release changes. The release page is the only current source.

### Is the mobile app the same product?

No. It shares the chain and can share a phrase, since a mobile phrase can be imported into the desktop wallet, but it has its own installer and release history.

## What this repository does not cover

It does not rank wallets, score them, or recommend one for a reader it has never met. It does not repeat the installation and recovery procedures, which belong to the setup collection, and it does not describe the application's internal architecture. It also does not claim an endorsement: no page states or implies that IoTeX or its foundation approves this desktop build, because no source read for these guides establishes that.

## Before you install

- **The release is v2.0.2, published 19 November 2026.** Three assets: one `.exe`, one `.dmg`, one `.zip`.
- **The build is identified by name, version, size and source page**, and by its SHA-256 value against the table in the app README, so a file that does not match can be rejected before it runs.
- **The phrase is the account.** A comparison should be decided before the first deposit, not after.
- **The app lock protects one machine.** It is not a recovery route and never replaces the phrase.
